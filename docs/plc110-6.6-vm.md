# PLC110 Android 16 boot image：6.6 内核离线验证

使用用户提供的 [boot_b.img](https://b.krtl.net/oplus/PLC110_16/boot_b.img)，
提取其中的实际内核在 QEMU 运行。此验证不刷写设备，也不等同于 PLC110 真机支持。

## 输入与构建

| 项目 | 值 |
| --- | --- |
| 内核 | `6.6.118-android15-8-ge58033dc8ea6-abogki498046332-4k` |
| 架构 / 页面大小 | ARM64 / 4 KiB |
| Boot 格式 | Android boot v4，legacy LZ4 压缩内核 |
| 编译器 | Android Clang 18，r510928 |
| 关键配置 | PID_NS、SYSVIPC、POSIX_MQUEUE 未启用；CFI_CLANG 启用 |
| 模块构建来源 | 独立 `src/port66/`，固定 android15-6.6 DDK |

输入 boot image SHA-256：

```text
c664a0ad0353da27ee65b16ade2b607912c98697b680489036489277746e2eec
```

解压后的原始内核 Image SHA-256：

```text
eda66d36df4936f7689ff6f7ebffad81726790bff39efbffae32332ac97cc4cd
```

QEMU 使用这份原始 Image，内核内容没有修改。模块的 `.modinfo` 中仅调整
vermagic 的 release 前缀以匹配它；其余 vermagic 配置项逐项校验。
测试加载器通过 kallsyms 重定位模块依赖，模拟 `ksud insmod` 的重定位步骤。

## 发现与修正

DDK 启用了 `CONFIG_PROC_EVENTS`，这份实际内核未启用 connector。
初次加载因缺少 `proc_exit_connector` 被测试加载器拒绝，尚未执行模块初始化。

移植的退出路径现通过 KallRecon 获取该可选回调：存在时保留原生退出事件通知，
在已知未启用该功能的 PLC110 内核上跳过。DDK 基线仍要求回调存在，避免静默丢失事件。
最初版本仅开放这两个已记录 release 的 QEMU 加载。后续真机测试版增加
`plc110_test=1`，仅为上述 PLC110 完整 release 显式开放手动加载；使用步骤见
[PLC110 手动测试说明](plc110-device-test.md)。

## 验证结果

完整测试通过，最终 `DS_VM_RESULT=0`：

- 连续 3 轮核心自测加载 / 卸载通过，再激活完整 hook。
- PID 1、嵌套 PID、procfs、孤儿回收、setns、权限和容器 reboot 通过。
- perf、BPF iterator、cgroup-v1 pidlist、FUSE 引用生命周期通过。
- memfd 可执行策略、seal、父级策略限制和宿主隔离通过。
- SysV 消息队列、信号量、共享内存、SEM_UNDO、阻塞删除与隔离通过。
- POSIX mqueue 挂载、优先级、超时、通知、隔离及 unlink 后 FD 生命周期通过。
- 最终 `pid_live=0`、`ipc_live=0`、`ipc_tasks=0`；激活后拒绝卸载符合预期。
- 日志没有 BUG、WARNING、Oops 或 Kernel panic。

6.6 基线没有 pidfd namespace ioctl，该项明确跳过；`SHM_HUGETLB` 返回
`EOPNOTSUPP` 的检查通过。修正后的模块也通过原 DDK 6.6.127 内核的完整回归测试。

静态核对：683 个共享结构体 / 联合体布局一致，20 个替换入口签名一致，
364 个可比对的依赖函数签名一致。最终 410 个模块依赖符号均由测试加载器解析成功；
运行时 20 个系统调用和 6 个 BPF 回调的 CFI 预检通过。
这些检查不构成任意 6.6 内核或未覆盖路径的兼容性证明。

## 复现

需要 Docker、Python 3 和宿主机 `lz4` 命令。先按
[6.6 构建说明](android15-6.6.md)准备 DDK 和 QEMU 工具。

```sh
mkdir -p out/plc110-6.6
curl --fail --location --output out/plc110-6.6/boot_b.img \
  https://b.krtl.net/oplus/PLC110_16/boot_b.img
./scripts/build-ddk-6.6.sh OUT=/module/out/plc110-6.6/build -j4
python3 scripts/abi/prepare-plc110-6.6-vm.py \
  out/plc110-6.6/boot_b.img \
  out/plc110-6.6/build/droidspaces_ns.ko out/plc110-6.6/vm
DS_VM_KERNEL=/work/out/plc110-6.6/vm/Image \
DS_VM_MODULE=/work/out/plc110-6.6/vm/droidspaces_ns.ko \
DS_VM_LOG_DIR=out/plc110-6.6/vm \
DS_TEST_PIDFD_NS_IOCTL=0 DS_TEST_SHM_HUGETLB_REJECT=1 ./tests/vm/run.sh
```

准备脚本检查 boot image 的固定哈希、内核格式、完整 release、配置和模块来源，
输出内核、BTF、配置、测试 `.ko` 及 `inputs.json`。
测试日志位于 `out/plc110-6.6/vm/console.log`。

## 范围限制

QEMU 使用 `virt` 平台、2 个 vCPU、2 GiB 内存和 initramfs，SELinux 关闭。
未覆盖设备驱动与调度扩展的实际运行、Android SELinux Enforcing、KernelSU 真机加载、
Droidspaces 完整容器启动及长期稳定性。已开放显式真机测试，但尚无真机通过记录；
不提供自动加载 ZIP。
其余限制与 6.6 实验构建一致，包括未接入 32 位 IPC，以及明确拒绝 `SHM_HUGETLB`。

最终模块 SHA-256：

```text

```

该二进制带 `plc110_test=1` 在原始 Image 上重新完成全部 QEMU 测试，
最终 `DS_VM_RESULT=0`，PID/IPC/task 计数全部归零，无内核告警。
加载脚本的 9 项隔离测试通过。额外修改虚拟机 root compatible 的试验没有启动输出，
不计入验证结论；当前没有模拟或验证 PLC110 的设备树和硬件。

构建后将 VM 准备脚本生成的匹配版本 `.ko` 打包：

```sh
python3 scripts/package-plc110-test.py \
  --module out/plc110-device-test/vm/droidspaces_ns.ko \
  --output out/plc110-device-test/package
```

此处输入目录可替换成上方复现步骤的 `out/plc110-6.6/vm/`。
复测显式参数可在 VM 命令中增加 `DS_VM_MODULE_PARAMS=plc110_test=1`。
