# v0.1.2 首次解锁重启

2026-10-10，PLZ110 安装 v0.1.2 后可以停留在锁屏，但首次输入密码后重启。
禁用模块后的下一次启动可以正常解锁。v0.1.2 Release 和附件已撤下；Git 标签保留。修复版为 v0.1.3。
保留的 v0.1.2 Git 标签不包含下述修正。

## 证据与原因

开机日志显示两个 LKM 加载和 Sandboxing 功能检查成功。连续日志在解锁 CE 存储后、
`vold: Mounting emulated fuse volume` 附近断开。pstore 为空；厂商
`/proc/last_boot_reason` 记录 `kernel crash Minidump`。

最小 FUSE 挂载测试在原始 GKI 与 PLZ110 boot image 的 QEMU 中均复现：

```text
DS_FUSE_BASELINE
DS_FUSE_MOUNT_OK
DS_FUSE_PASS
DS_FUSE_WITH_USERNS
Unable to handle kernel NULL pointer dereference at virtual address 00000000000000ac
pc : ds_fuse_conn_init+0x1a4/0x294 [droidspaces_ns]
Kernel panic - not syncing: Oops: Fatal exception
```

原内核 `CONFIG_USER_NS=n`，`get_user_ns()` 忽略参数并返回初始 namespace。
编译器因此省略了 `fuse_get_tree()` 向 `fuse_conn_init()` 传递的第三参数（x2）。
LKM 在 `CONFIG_USER_NS=1` 下重新编译此函数，却读取了原调用者没有传入的指针。
FUSE 新连接创建时即发生空指针访问。原有 PID/IPC 载荷未读取该参数，所以没有触发。
先前手动加载时 Android 的 FUSE 存储已挂载；Sandboxing 回归没有再次创建 FUSE 连接，
因此遗漏了这个故障。

## 修正候选与边界

原生 FUSE 连接入口保持初始 user namespace 所有权，完全不读取失效的第三参数。
`fuse_get_tree()` 入口校验 `fs_context` 的所有者，非初始 user namespace 返回
`EOPNOTSUPP`；FUSE 其他内联身份转换尚未移植，不允许把沙箱创建的 FUSE 静默归给宿主。
现有 Android 宿主 FUSE 挂载保留原生语义。此修正没有改成延时加载来避开复现。

补充回归包括加载前后的宿主 FUSE 挂载/释放，以及拒绝沙箱创建 FUSE。
两颗内核已通过新增回归和已有的 22 项策略、32 轮竞态、三种 Bubblewrap 及实际
Droidspaces 容器测试，均保留 HMA 共存测试。790 项聚合布局匹配，导入符号和可比较
函数原型没有新增差异。修正版已在同一 PLZ110 上通过实际开机自动加载、首次密码解锁及文件管理器使用，
Android 的 `/mnt/user/0/emulated` 和 `/storage/emulated` FUSE 挂载正常。
开机后再次通过 FUSE、完整 Sandboxing、PID / IPC / POSIX mqueue 真机回归，
全局 SELinux 保持 Enforcing。该结果属于修正后的候选，不适用于原 v0.1.2 资产。

本地证据：`out/boot-crash-v012/` 与 `out/userns-fuse-fix/`。
手机系统日志可能包含个人信息，不随仓库或 Release 分发。
